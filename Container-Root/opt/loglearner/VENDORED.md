# LogLearner minimal runtime - vendored copy

This directory is the gated **minimal runtime** of [LogLearner](https://github.com/dmvevents/loglearning)
(the dashboard over an agent's Claude Code sessions, the `loglearner` package with its knowledge-pack loader,
`recall` and `bank` commands, and the optional PreToolUse rule-delivery hook), shipped inside the image at
`/opt/loglearner` so the `LogLearner dashboard` tile works out of the box. The repository is public and carries
this minimal runtime only (tag `v0.1.13`); upstream development is private.

This tree is the artifact's, with one exception: this repository's hardening (no behavior change) is applied to two
files the release ships without it - `dashboard/app.py` (the sessions query is one static statement with every filter a
bound parameter) and `dashboard/indexer.py` (table names quoted as SQL identifiers, embedded quotes doubled). The other
two files of that hardening, `loglearner/arms.py` and `loglearner/steps.py` (SHA-1 used for ids only,
`usedforsecurity=False`), carry it upstream since 0.1.13. The artifact ships no deployment data file and no internal
identifiers.

Deliberately left out upstream (by the artifact's construction): the raw session index, ledgers, the
knowledge indexes, the real scrub patterns (the shipped `config/scrub-patterns.example.json` carries FAKE
values), the embedding matcher (sentence-transformers), the gist and Slack sources, and the planted-secret
test suites. The upstream rule-MINING command is not part of the runtime; the `loglearner` command the image
installs (`setup/install-loglearner.sh`) is the runtime's own `python3 -m loglearner.cli`: `recall`, `bank`,
and the pack loader's `ingest | verify | installed`.

In the container `/agent/loglearner-serve.sh` keeps the runtime's state under `/wd/loglearner` (index, banks,
ledgers), loads the harness's starter rules (`/seed/loglearner-rules.jsonl`) into its global instinct bank on
every start (idempotent), indexes the agent's own sessions and serves the dashboard on 127.0.0.1 behind the home
proxy (`http://loglearner.localhost:8000/`; `/api/tile.json` is its status contract). The PreToolUse hook under
`scripts/hooks/` is wired into the agent's settings by `/agent/loglearner-hook.sh` (`LOGLEARNER_HOOK`,
docs/manual/memory.md "Agent learning tools"), and `/agent/recall.sh` and `/agent/learn.sh` wrap the `recall` and `bank` commands.

Refresh with `tools/vendor-loglearner.sh <tarball> <path-to-loglearning-clone>` from the repository root: it copies
the release as it is, so carry the two files' hardening over by hand (compare them with the release's) and update
the sha above.

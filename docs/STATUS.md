# Status - completion checklist

Checklist against the four goals in README.md, plus delivery. A row that cites a run names the run
and its date (UTC); every other row is read from this tree.
`shipped` = in the tree with a test that fails if the thing is removed. `open` = not in the tree, or
in it without such a test. `verified` = run on the date given, with the result given, on a revision of
the harness before its public release.

## How to tick a row

`./build.sh && ./test.sh`. `test.sh` prints `Running test /testN.sh` for each one; a row ticks when
its test ends with `TestN succeeded` (`test-exec.sh` ends with `Test-exec PASSED`; most print
`ok N - ...` per property first). `test3.sh` needs Bedrock credentials and otherwise prints
`Test3 skipped`, so a green suite without credentials does not tick the loop rows.
compose: `TO=compose` in `.env` (and `DOCKER_COMPOSE="docker compose"` where the Compose plugin
is installed but no `docker-compose` binary), `./run.sh`, `./status.sh`, then
`curl -sf http://localhost:8000/ | grep -q "do-agent-aws harness" && echo home up`.
kubernetes: `TO=kubernetes`, `./run.sh` (renders into
`to/kubernetes/app/` and applies), `./status.sh`, `kubectl -n do-agent-aws port-forward
svc/do-agent-aws 8000:8000`, same curl. Persistence rows have no test: compare
`ls -la wd/agent-state/.claude-mem` before and after `./stop.sh && ./run.sh`.
Memory: `docker exec do-agent-aws /agent/hindsight-seed.sh --status` prints the seed stamp and the per-bank
counts; `curl -s http://localhost:8000/memory-api/v1/default/banks` lists the banks with their fact counts -
compare before and after `./stop.sh && ./run.sh` for the persistence row. `test15.sh` and `test17.sh` run
without credentials; their extraction sub-checks (memories, not just documents) need Bedrock and otherwise
print a skipped line, so a green suite without credentials ticks the store and seed rows, not the extraction.
Sandbox: `to/sandbox/test/test1.sh` to `test4.sh` need neither sign-in nor KVM; the row ticks
when `to/sandbox/test/e2e.sh --cloud --kit <pushed kit image>` (or `--local` on a KVM host),
run with the model credential configured (a sandbox-scoped bedrock secret and its binding, `to/sandbox/README.md` "Model credential"), exits 0 with `summary.json` overall `PASS` and the
`agent` and `teardown` layers `PASS` (`to/sandbox/README.md`).
The comms engine pin row ticks when the pin in `setup/install-comms.sh` moves to an engine release with the gated
Slack send, with `test6.sh` check 2 passing on the new sha.
